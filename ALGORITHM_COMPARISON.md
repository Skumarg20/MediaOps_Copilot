# Graph-Augmented Retrieval — Architecture Comparison

**9 retrieval architectures × 7 domains × 83 queries × 12 intent categories.**
Every number below is produced by code in this repository and regenerated by one command.

```bash
docker compose up -d neo4j
npm run graph:sync   --workspace=apps/api     # load 7 domains into Neo4j
npm run graph:verify --workspace=apps/api     # 15 assertions against live Neo4j
npm run eval:architectures --workspace=apps/api   # → ml/algorithm_comparison.md
```

---

## 0 · The problem this solves

The retrieval layer had **two mutually exclusive paths over disjoint content**:

```
BEFORE
  query ──► router ──► pick ONE ──┬──► vector      dense embeddings over ~34 runbook chunks
                                  └──► vectorless  BM25 over 20 job / error-code records
                                                   topK = 3, one hop, one direction
```

| # | Failure | Evidence in the fixture data |
|---|---|---|
| 1 | Runbook prose not keyword-searchable at all | BM25 indexed only records — embedder down ⇒ entire prose corpus invisible |
| 2 | Records and prose were disconnected islands | `how do I fix job 482` returned the job and the code, **never the runbook** holding the drain-vs-retry judgement |
| 3 | The paths competed instead of combining | The bandit optimised *which single path wins*; a diagnostic question needs the record **and** the prose |
| 4 | Whole question classes unanswerable | *"which worker fails most"* — answer is `worker-07`, 3 of 7 failures, and top-*K* cannot count. *"which codes have no runbook"* — 5 of 8, and similarity returns only what matches |
| 5 | Evaluation was blind to all of it | 40 golden cases, zero aggregation / complement / comparison / temporal |

**Diagnosis:** relevance was modelled as similarity between a query and *one chunk*.
Whenever the answer is a property of how records **relate**, that assumption is false, and
no amount of top-*K* or better embeddings repairs it. §4.3 quantifies it: the four
text-based architectures score **13 / 220 (5.9 %)** on structural categories.

Three things were deliberately **not** built:

| Not built | Why |
|---|---|
| LLM entity extraction | Entities are already typed rows; extraction adds only noise. LightRAG's far richer extracted graph — 244 entities vs a reference implementation's 48 — still failed the structural queries |
| Community detection + summarisation | Earns its cost on large narrative corpora, not on 13 KB of runbooks that fit in a context window |
| Text-to-Cypher | Typed operators have no generated-query injection surface and no syntax failures |

## 2 · System design

### 2.1 Storage and execution

```
 ┌──────────────┐   seed at boot    ┌──────────────────┐
 │ JSON / TS    │──────────────────►│  Postgres        │  platform.job
 │ fixtures     │                   │  (records)       │  platform.error_code
 └──────────────┘                   └────────┬─────────┘
                                             │ Knex SELECT
 ┌──────────────┐   chunk                    ▼
 │ markdown     │──────────────►  buildMediaOpsDataset()
 │ runbooks     │                            │
 └──────────────┘                            ▼
                                    ┌──────────────────┐
                                    │  DomainDataset   │  nodes · edges · schema
                                    └────────┬─────────┘
                                             │ Neo4jGraph.sync()
                                             ▼
                                    ┌──────────────────┐
                                    │     Neo4j 5      │  :Entity + type label
                                    │   + GDS plugin   │  validFrom / validTo on edges
                                    └────────┬─────────┘
                                             │ Cypher / GDS
                        ┌────────────────────┼────────────────────┐
                        ▼                    ▼                    ▼
                 15 operators        hybrid retriever        benchmark
```

### 2.2 The four search paths

| | Answers | Index | Signal | Model call |
|---|---|---|---|---|
| `vectorless` | "what is this record" | 20 records | exact key → BM25 | no |
| `vector` | "explain / why" | ~34 prose chunks | cosine | **yes, hard dependency** |
| `hybrid` | "how do I fix X" + structural | all 68 nodes | all three, rank-fused, graph-expanded | degrades without |
| operators | "how many / which have none / rank by" | Neo4j | Cypher + GDS | no |

### 2.3 Hybrid retrieval pipeline

```
 ①  SEED ─ exact anchors      w=2.0 ─┐
          BM25   ≥1.2 & cov ≥0.5     ├─ each subject to the SAME floors
          dense  ≥0.45 & (≥0.7|≥0.4) ┤  the single-signal paths use
          type-name seeds     w=0.5 ─┘
                    │  no seed clears a floor → ABSTAIN
                    ▼
 ②  FUSE ─ Reciprocal Rank Fusion   score = Σ w /(60 + rank)
                    │                rank-only: BM25 sums and cosines
                    ▼                never need calibrating
 ③  EXPAND ─ Cypher  (s)-[*1..2]-(m)   score = seed × decay[hops] × 0.9
                    │                   decay = [1, 1, .6, .35, .2]
                    ▼                   records hopPath + edge types
 ④  RANK ─ score desc, then hops asc   (direct match beats neighbour)
                    ▼
 ⑤  MMR ─ 0.7·relevance − 0.3·maxJaccard
                    ▼
 ⑥  CAP ─ top 6, each carrying provenance
```

**Abstention guard:** expansion runs *only* from seeds that already cleared a floor.
All 7 out-of-domain queries abstain — A9 column, rows M12 / C12 / AE12 / RE12 / MF11 / LG12 / FN12.

### 2.4 Operator vocabulary — 15 typed operations

| Tier | Operator | Implementation | `operators.ts` |
|---|---|---|---|
| Traversal | `find_nodes` | `MATCH (n:Entity) WHERE …` | L56 |
| | `get_node` | property lookup | L86 |
| | `get_neighbors` | `-[r]-` + validity filter | L98 |
| | `shortest_path` | `shortestPath()` | L134 |
| | `subgraph` | `-[*1..N]-` | L158 |
| | `count_edges` | `count(r)` | L188 |
| | `set_complement` | `WHERE NOT n.id IN $exclude` | L203 |
| | `filter_edges_by_date` | `WHERE r.validFrom >= $from` | L227 |
| | `propagate_risk` | weighted `min(length(path))` + decay | L262 |
| Computation | `simulate_removal` | subquery counting surviving links | L329 |
| | `subgraph_diff` | two expansions compared | L377 |
| | `aggregate_over_type` | `collect(DISTINCT t)` + `ORDER BY` | L439 |
| | `pagerank` | **`gds.pageRank.stream`** | L539 |
| | `betweenness` | **`gds.betweenness.stream`** | L553 |
| | `connected_components` | **`gds.wcc.stream`** | L567 |

Centrality and components project the subgraph **induced by the type asked about** — hub↔hub lanes, account↔account counterparties — so "which hub is the bottleneck" is a question about the lane network, not about whatever shipment touches two hubs.

```cypher
MATCH (a:Hub {domain:$domain})-[r]-(b:Hub {domain:$domain})
RETURN gds.graph.project($name, a, b, {}, {undirectedRelationshipTypes:['*']})
```

### 2.5 Why aggregation needs its own operator

```
 "which line produced the most defects"        (manufacturing, 3 hops)

 A6  9 primitives          A7  15 operators
 ──────────────────        ─────────────────
 count_edges(LN-01)        aggregate_over_type(
 count_edges(LN-02)          rootType : Line,
 count_edges(LN-03)          targetType: Defect,
 count_edges(LN-04)          maxHops  : 3 )
 count_edges(LN-05)
 count_edges(LN-06)        ← 1 call, complete ranking
 ← 6 calls, budget gone
 verdict: PARTIAL          verdict: CORRECT
```

Each **computation** operator encapsulates a complete algorithm, not a step.
Measured across 83 queries: 62 → **76** correct, while calls/query *fall* 2.6 → **1.5**.

Each corpus carries a deliberate trap:

| Domain | Trap | Why it matters |
|---|---|---|
| aerospace | ShenzhenChip contract expired 2024-02-16; TechChip took over 02-17. Both in the prose. | Temporal — text retrieval returns both, cannot choose |
| retail | `PRD-08` listed, never ordered | Absence — similarity can only return what matches |
| manufacturing | `MCH-09` is the only machine on `LN-05` | Counterfactual — defined by what is missing after an edit |
| logistics | Dubai is the sole crossing E↔W; Perth–Auckland connected to nothing | Cut vertex + disconnected component |
| finance | `ACC-11/12/13` transact only with each other | Closed group — isolation is invisible to similarity |

`aerospace` is reconstructed from the reference paper's published schema and ground-truth tables. It reproduces the headline findings — 15/15 components single-sourced, 11/3/1 criticality split, exactly one customer outside the Thailand-flood blast radius — all asserted in `test/domains.test.ts`.

## 6 · The measurement gap

The reference paper warns that entity-level F1 **underscores** structural queries. It reproduces here:

| Query | A9 verdict | Recall | Precision | F1 | Why |
|---|---|---|---|---|---|
| FN5 closed group | CORRECT | 1.00 | 0.33 | **0.50** | returned the 3 nominee accounts + supporting context |
| LG3 bottleneck | CORRECT | 1.00 | 0.07 | **0.13** | one right hub + 14 evidence nodes |
| RE2 seller returns | CORRECT | 1.00 | 0.29 | **0.44** | right seller + the orders proving the count |

Every extra **correct** entity counts as a false positive. This is why A9 leads on correctness (81) while trailing A7 on F1 (0.440 vs 0.557) — it returns evidence alongside the answer.

> **Rule applied:** verdict and F1 are reported side by side and never averaged.
> Aggregation needs ranking accuracy; complement needs set correctness; what-if needs causal coverage.

## 8 · Limitations

| | |
|---|---|
| **Planner is deterministic, not an LLM** | A6/A7/A9 use an intent→operator planner. This removes tool-choice error, making them an **upper bound**. It isolates the variable under test — operator vocabulary — with model quality held constant. |
| **Dense baseline is an offline embedder** | Not a trained sentence-transformer. Absolute A2 numbers are indicative; the direction is not in question — structural categories fail for reasons unrelated to embedding quality. |
| **Corpora are synthetic, 41–74 nodes** | Enough to separate architectures whose gaps are categorical. Says nothing about corpus-scale retrieval. |
| **Single query per category per domain** | A lucky ordering flips one cell. A2 scores `correct` on LG3 purely by chance. Read totals and the category matrix, not single cells. |
| **Benchmark is no longer offline** | Requires Neo4j + `graph:sync`. Per-query latency rose ~3 ms → ~70 ms (network round trips). Results unchanged. |
| **Hybrid retriever ignores `asOf`** | The graph carries validity and the operators honour it; `HybridRetriever` expands without a reference instant, because `QueryContext` has none. Temporal questions are answered by the operator layer. |
